模型配置

对话模型
例如 qwen-plus、qwen-max、gpt-4o
须为 OpenAI 兼容地址，通常以 /v1 结尾。默认端口 Ollama 11434 ｜ vLLM 8000 ｜ LM Studio 1234 ｜ llama.cpp 8080
可用下方按钮从服务器拉取实际可用的模型列表
Ollama 会忽略此项；vLLM 若启用了 --api-key 则需填写
嵌入模型
切换来源会重建向量库，需要重新索引已上传的文档
中文知识库务必使用支持中文的模型
检索与生成
每次检索返回的最相关文档片段数量
低于该值的片段被丢弃。只作用于向量这一路，BM25 命中的片段不受影响
检索增强（可独立开闭以做对比）
向量检索靠语义，对 kubectl exec、错误码这类精确串很弱，BM25 正好互补
术语和新词多的语料可以对比两者再定
越大则头部名次的优势越小，60 为原论文取值
对候选做精排，精度更高但耗时明显增加；首次启用需下载约 1GB 权重
中文请用 bge-reranker-base 或 jina-reranker-v2-base-multilingual
交叉编码器输出未归一化，不同模型取值范围差异很大，需实测后再定
开启融合或重排时每路先取这么多候选，再截到 Top K。太小会让重排无从改进排序
